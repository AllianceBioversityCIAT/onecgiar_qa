# src/common — Agent Guide

The HTTP surface shared by `main.ts` and the e2e suites, so tests exercise the real bootstrap. Root and `server/AGENTS.md` rules apply.

## Files

| File | Role |
|---|---|
| `configure-app.ts` | `configureApp(app)` and `API_PREFIX` (`api/v1`): trust proxy (1 hop), global prefix, request id, helmet, cookie-parser, global `ValidationPipe` (`whitelist`, `forbidNonWhitelisted`, `transform`), global `HttpExceptionFilter`, CORS (exact-origin echo from `ALLOWED_ORIGINS`, credentials, never `*`), and body parsing (JSON everywhere; urlencoded everywhere except `/api/v1/auth`; no text parser; JSON-only gate on auth POSTs) |
| `error-codes.ts` | **The error catalog**: every `code` with its status and user-facing message; `errorBody(code)` for domain exceptions; `genericCodeFor(status)`; the per-field codes (`FIELD_ERRORS`) |
| `api-response.ts` | The response standard: `ApiSuccess` / `ApiFailure` / `ApiMeta` types (`meta.page?` = `{ nextCursor }` on a paginated list), `Paged` (what a list handler returns), `metaFor`, the OpenAPI models, `@ApiOkEnvelope(data, { description?, extraModels?, status?: 200 | 201, paged?: boolean })` (`data` is a model class or an inline schema; the users and catalogs controllers build array schemas with a local `listOf(Model)` and name the model in `extraModels`) and `@ApiErrorResponses({ status: [codes] })` |
| `response-envelope.interceptor.ts` | Global: wraps every handler result as `{ success: true, data, meta }`; a `Paged` result becomes `data: items` and `meta.page.nextCursor`; `undefined` (204) stays empty |
| `validation.ts` | `validationExceptionFactory` (class-validator errors → `VALIDATION_FAILED` with `fields` in our words, `TOO_LONG` with the limit from the `max` context; nested names: objects join with a dot, array items with brackets — `roles[0].role`, `exclusions[0].createdBy`) and `bodyParserErrors` (broken JSON → `MALFORMED_JSON`, too large → `PAYLOAD_TOO_LARGE`) |
| `http-exception.filter.ts` | Every error → `{ success: false, error: { status, code, message, fields?, retryAfter? }, meta }`. Text only from the catalog: a domain error's code, else the status's generic code; `retryAfter` from the throttler header; 5xx logged by fixed fields (`errorFacts`) |
| `openapi.ts` | `buildOpenApiDocument(app)`, `setupOpenApi(app)` (Swagger UI at `/api/v1/docs`, JSON/YAML under it, `persistAuthorization`), the security scheme names `ACCESS_TOKEN_SCHEME` / `SESSION_COOKIE_SCHEME`, and `@ApiErrorResponses(...statuses)` (the error envelope per status). Called from `main.ts` only when `OPENAPI_ENABLED` resolves to true — not from `configureApp`, so the e2e router inventory is unaffected |
| `startup-checks.ts` | `runStartupChecks(app)` (from `main.ts` only): logs once whether MySQL answers `SELECT 1` and whether the DynamoDB table answers `DescribeTable` (status, keys, `credentials=explicit keys\|default chain`). Background, 5 s timeout each, never blocks or stops the API; failures are a `WARN` with a fixed reason (driver code or AWS error name, never the message) |
| `idempotency/` | Route-scoped write safety (`@Idempotent()`, users-admin-write-safety). `idempotent.decorator.ts` applies `IdempotencyInterceptor` and documents the `Idempotency-Key` header; `idempotency.interceptor.ts` reserves `(actor, key)` before the handler and replays, refuses, or runs; `idempotency.store.ts` is the port (`IDEMPOTENCY_STORE`) and the MySQL adapter `DrizzleIdempotencyStore` (`reserve`, `find`, `takeOver`, `markExecuted`, `complete`, `release`, `purgeExpired`) plus the constants `IDEMPOTENCY_LEASE_MS` (120 s), `IDEMPOTENCY_RETENTION_MS` (24 h), `IDEMPOTENCY_PURGE_BATCH` (50); `idempotency.context.ts` carries the reservation to the handler (`@CurrentIdempotency()`); `fingerprint.ts` (sha256 of method + path + canonical body); `idempotency.errors.ts`; `idempotency.openapi.ts` (header docs, `withIdempotencyErrors`) |
| `request-id.ts` | `requestIdMiddleware`: reuses a valid incoming `x-request-id` or creates one, echoes it on the response; `requestIdOf(request)` for logs and the envelope |

## Rules

- **One wiring path.** Any global middleware, pipe, filter or parser goes into `configureApp`, never only into `main.ts` — otherwise e2e tests stop matching production.
- **Order matters:** request id first (every later step and log line sees it); the JSON-only gate on `/api/v1/auth` runs before any body parser reads the body.
- **CORS:** keep the exact-match callback. Do not switch `origin` to `true`, a regex, or `*` (FR-16; the CORS e2e fails).
- **Response standard:** keep the field set stable — the front and the tests depend on it. Every client-visible text comes from `error-codes.ts`; adding a code is the way to say something new. `fields` only for `VALIDATION_FAILED`; a field path names an array item with brackets (`roles[0].role`) and a nested object with a dot — service-level checks use the same form, and the front depends on it. A list endpoint returns `new Paged(items, nextCursor)` and declares `@ApiOkEnvelope(Model, { paged: true })`; a route answering 201 declares `status: 201`. Never put stack traces, SQL, upstream bodies or user data in a response.
- **OpenAPI:** the docs routes are registered on the Express adapter, outside the Nest guards. Keep them off in PROD unless enabled on purpose: the document maps the whole API surface. `ErrorEnvelope` is a class so the document can describe it; keep its fields in step with the filter.
- **Idempotency (opt-in per route, DD-6).** Add `@Idempotent()` to a write handler, wrap its error list in `withIdempotencyErrors`, pass `IDEMPOTENCY_REPLAYED_HEADERS` to its `@ApiOkEnvelope`, and bind `IDEMPOTENCY_STORE`, `IDEMPOTENCY_CLOCK` and `IDEMPOTENCY_REPLAY_READER` in the module (see `users.module.ts`). Behavior, all in `idempotency.interceptor.ts`:
  - **Target id (`idempotency_keys.target_user_id`).** The column keeps its historical name and has no foreign key; the replay reader of each module decides what the id means. Users routes store a user id. `src/admin-config/` stores a **cycle id** for `POST /cycles`, a **timeline id** for `POST /cycles/:id/timelines` and `PATCH /timelines/:id`, and a **version id** for `POST /cycles/:id/field-config/publish`; each of its three modules binds a reader that re-reads that entity. A new keyed route in another module states its meaning in that module's guide.
  - No `Idempotency-Key` header: the route is untouched. A malformed key (not 1-128 of `A-Za-z0-9-_.:`) is 400 `VALIDATION_FAILED` on field `Idempotency-Key`; nothing is stored.
  - Guards run first, so a 401/403 never reserves a key. The interceptor purges up to 50 expired rows, then reserves; any store failure is 503 and the handler does not run.
  - Same key and same fingerprint: `completed` replays the stored answer (success `data` through the envelope, a stored 4xx re-thrown from `{ code, fields }` and its status) with `Idempotency-Replayed: true`; `executed` without an answer replays the route status with a fresh read of the target (`IDEMPOTENCY_REPLAY_READER`); `in_progress` with a live lease is 409 `IDEMPOTENCY_IN_PROGRESS`; an expired lease is taken over by compare-and-set on the old owner token. Same key, other fingerprint: 422 `IDEMPOTENCY_KEY_REUSED`.
  - After the handler: a 2xx or a deterministic 4xx is remembered; 5xx and unknown errors release the key so a retry runs again. The change itself is fenced by the service marking the key `executed` in the business transaction (`users-admin.service.ts` `markExecuted`), never by the interceptor.
  - **Logging (NFR-2, FR-9).** The interceptor writes its own `event:"idempotency"` line only for `replayed`, `in_progress` and `reused`, with ids and fixed words (`idempotency`, `outcome`, `status`, `actorId`, `requestId`), and three error-level or warn-level lines: `settle_failed` and `complete_failed` (error) and `complete_lost` (warn, the lease was lost before `complete` stored the answer); a first or taken-over run writes no line here (the service line carries `idempotency=none|taken_over`). Never the key, the fingerprint, a stored body or the request body. `test/users-admin-idempotency-privacy.e2e-spec.ts` pins this over every logger.
- `trust proxy = 1` assumes exactly one reverse proxy in TEST/PROD (premise P-16); revisit throttling if that changes.

## Testing

`idempotency/*.spec.ts` (fingerprint table, store over a SQL-driver fake, interceptor over fakes); `test/users-admin-idempotency.e2e-spec.ts` (every keyed route over HTTP) and `test/users-admin-idempotency-privacy.e2e-spec.ts` (log spy). `http-exception.filter.spec.ts` and `request-id.spec.ts` (unit); `test/openapi.e2e-spec.ts` (document = router, security per route, schemas, UI served when set up); the CORS, envelope, 404 and body-parsing behavior is covered in `test/app.e2e-spec.ts` and `test/auth-login.e2e-spec.ts`.
